## Findings considered and rejected

- **RTL panel direction**: The panel opens from the left edge in an RTL app. In RTL, the left edge is the "end" side — this is actually correct for a navigation drawer. The panel toggle uses `chevron-forward`/`chevron-back` icons which adapt to RTL. No fix needed.
- **Bottom sheet migration**: The control panel is a full-height sidebar. The mobile-native pattern would be a bottom sheet (half/full sheet). This is a larger refactor and noted as future direction — not included in this batch of plans.
- **Persistent GPS tracking**: The current GPS is one-shot. Adding `watchPositionAsync` with a toggle is a feature enhancement, not a UI fix. Noted as future work.
- **Neshan API migration**: Replacing Nominatim/OSRM with Neshan for better Iran coverage. Out of scope — current free APIs work. Noted in plan 001 index.
- **Test infrastructure**: No Jest/Vitest configured. Adding tests is a separate initiative. Verification in these plans is via lint + typecheck + manual.
- **Dark mode support**: Significant effort for a color-themed app. Deferred to future work.
- **Orientation lock**: Locking to portrait is common for map apps but not strictly necessary since the layout already works in both orientations. Low priority.
- **Concurrent Promise.all for OSRM routes**: Rejected per plan 001 notes — OSRM public demo server 429s concurrent requests.
- **Stale closure in SearchBar debounce**: The `handleSearch` callback has `[]` deps but receives `value` as a parameter from `onChangeText`, so it's not actually stale. The search works correctly.
